# Split-bar interaction study

The user wants a single allocation bar with draggable tabs at color boundaries, exact tag amounts and remove controls next to those amounts. One selected tag begins at 100%; its end tab can release money into gray Other. This is an isolated, disposable mockup using $128.60 of synthetic data. It has no application API, database, imports, or persistent writes. Do not integrate it before the user's feedback.

Run from the repository: `node node_modules/vite/bin/vite.js --config prototypes/split-bar/vite.config.mjs`. Open http://127.0.0.1:4182. `node prototypes/split-bar/check.cjs` checks the running prototype in headless Chrome and saves screenshots under ignored private/validation.

Compare Inline (name, amount and remove in wrapping rows), Mini grid (three compact columns), Integrated (amount cells and rail in a single inset surface), and Original rail as a baseline. All use exactly the same allocation model and preserve state when switching. Inline is the initial view. Precision, even split and undo share one toolbar; available tags remain visible. With five tags at 1280px, the cards measure 402px, 393px and 381px versus the original 562px. The previous roomy ribbon is no longer offered in the comparison. Editable labels have their own legible width rather than shrinking with tiny monetary sections. The design question is which presentation makes the amount relationship easiest to read and manipulate in a future compact transaction card.

Trial assumptions: Other is always the final allocation, hidden when zero except for the usable end tab. Moving a divider transfers only between its two neighbours. New tags consume Other first; with no remainder they receive half the largest existing section. Removing a tag sends its amount to Other. Decreasing an exact amount sends the released money to Other; increases draw from Other first, then from other tags in reverse order. Split evenly explicitly rebalances all chosen tags and clears Other. These choices are provisional and should be refined through use, not treated as approved application rules.

Dollar/cent precision, keyboard arrows (Shift for ten steps), Home/End, direct amount edits, local undo, one/two/five-tag presets, reduced motion and a simulated Save are included. Refresh resets everything. Browser checks cover cent conservation, pointer and keyboard dividers, Other remainder, add/remove, undo and tiny slices; they do not establish user preference or production integration readiness.

September 18 compact iteration: browser checks and visual inspection cover two/five tags, six entries including Other, one-cent amounts, layout switching, removal/undo, and 900px-wide desktop layouts.
