# Codex suggestions

October 4, 2026. Urbanomics can use a ChatGPT subscription, through the Codex CLI, to suggest how to organize the workspace. Four features: Suggest missing tags, Suggest a restructure, Suggest aliases, and Smart organizing on the Organize desk. Codex never changes anything itself: every suggestion is reviewed and approved in the app, then saved through the same versioned APIs as a manual change.

## Connecting (Settings → Codex)

- **Codex CLI.** The app looks for `codex` on `PATH` (and npm's global folder). For an npm install it runs the native binary from the platform package directly, never through a shell. If Codex is missing and Node.js is present, Install Codex runs `npm install --global @openai/codex@latest` (as `node npm-cli.js`, no shell) and shows npm's progress. `URBANOMICS_CODEX_PREFIX` makes the app look, and install, only in that prefix; the smoke script uses it so the computer's own Codex is untouched.
- **Account.** Sign in with ChatGPT starts the CLI's own login through `codex app-server` (`account/login/start`) and opens the returned OpenAI page in the person's browser (the desktop app uses the system browser; the browser host opens a tab). The page follows `account/login/completed`. Codex keeps the credentials in its own `CODEX_HOME`; the app never sees them. Sign out calls `account/logout`. Status, plan and the model list (`model/list`, hidden models excluded, with each model's reasoning levels) come from the same app server, started on demand and stopped after ten idle minutes.
- **What Codex can read.** A consent checkbox must be on before any feature runs. It states what is sent: descriptions, amounts, dates, account names, tags, people and events, to OpenAI under the person's account, only while a feature runs.
- **Features.** Each feature has its own model and reasoning level (Codex default when blank). Smart organizing has an on/off switch, here and in the Organize heading. Settings live in the private workspace `settings` table (`assistant` key); they are not part of the configuration export, and Start from scratch clears them.

Remote phone access cannot install, sign in or sign out (the web host refuses those calls when it serves the desktop); suggestions themselves work from any host.

## How a run works

Each request is one `codex exec` with `--ephemeral --skip-git-repo-check --ignore-user-config --ignore-rules --sandbox read-only --json --output-schema <file>`, the chosen `-m` model and `-c model_reasoning_effort`, started in an empty temporary folder with the prompt on stdin. So Codex sees only the prompt, cannot write, does not load the person's Codex configuration or hooks, and must answer in the feature's JSON schema. At most three runs share the account at once; a run times out after four minutes. Errors from the CLI (not signed in, model unavailable) are shown as they come.

`electron/ai/prompts.mjs` builds each prompt and validates each answer. Validators keep only what points at real things (existing ids, offered candidates, names that don't already exist), fix what can be fixed (cents that must add up, a "new" category that already exists) and drop the rest. The Other fallback tag is never offered.

## The features

- **Suggest missing tags** (Settings → Categories & tags → Suggest). Codex sees the categories and tags with usage counts and up to 250 transaction names (untagged first) with direction, count, total and current tags. It proposes up to 12 new tags, each with an existing category, a new category or none, a reason and the names it fits. The review lets you uncheck, rename and recategorize each, and offers to tag the matching transactions that have nothing on them yet (only rows with no tags, repayment or transfer). Approving creates the categories, then the tags, then tags those rows with the whole amount through `organize`.
- **Suggest a restructure** (same menu). Codex sees the structure with usage, rules and example names per tag. Changes are create-category, create-tag, rename, move, merge and delete. With fewer than three tags (a new workspace, or after Start from scratch) the prompt asks for a complete starting structure of 4 to 8 categories and their tags, and lists the transactions so each new tag carries the names it fits; the review offers to tag the untagged ones, as Suggest missing tags does. The empty Categories & tags page offers "Suggest a structure from my transactions". Transfers, card payments and e-transfers with friends are never made into tags, in either feature. Each tag takes one change (a merged tag takes no other); deletes are limited to unused tags that are not merge targets and categories the plan empties; a move into a new category, or a category delete, is tied to the changes it needs. Approved changes apply in order (create, rename, move, merge, delete) and each reports its outcome. Merge is a new server operation, `review:merge-tags`: one transaction moves every portion (bank and cash, archived accounts too) and every rule or template reference from one tag to the other, summing portions on rows that had both, deletes the source tag and writes a private recovery copy under `backups/admin`.
- **Suggest aliases** (Settings → Aliases → Suggest aliases). Codex sees up to 400 descriptions without an alias, with counts, and the existing aliases. Each suggestion is a name plus a plain sentence (starts with, contains, ends with, is exactly) that compiles to the same pattern as the alias editor. The server previews each with the alias store's own check; ones that match nothing are dropped and clashes are shown. Editing a sentence re-runs the preview. Approved aliases save one by one through `saveAlias`, which still refuses overlaps.
- **Smart organizing** (Organize). With the switch on, opening an unsorted row asks Codex about it and prefetches the next unsorted row. The context is what the describe box already offers for that row: tags for its direction, people (with what they owe on money in), the 30 events nearest its date, likely transfer twins, expense categories, and up to 25 earlier rows with the same name or a similar description and how they were organized. Codex can suggest tags with amounts, one new tag when nothing fits, a twin, a person settling up, people to share with, a payee and an event. The card shows each with its reason and a checkbox (low-confidence ones start unchecked) and Apply. Applying uses the desk's own gestures in an order that keeps cents adding up: a twin alone (plus an event), otherwise settling first, then tags and the event in one save, then the split, then the payee; a new tag is created first. The flow then moves to the next unsorted row as a manual tag would, and Undo works as usual. Answers are remembered for the session by what was asked. Sorted rows offer "Ask Codex what this is" instead of asking on open.
- **Suggest for all unsorted** (Organize heading). Asks Codex about every unsorted row, newest first, through a pool of slots (October 5, after a 300-row run lost about half its rows): Settings → Codex sets how many Codex runs go at once (1–8, default 4, which is also the CLI concurrency limit) and how many transactions each run takes (1–10, default 5; `ai:suggest-organize-batch`, `organizeBatchPrompt`, each row with its own candidates and validated on its own). A slot that finishes takes the next rows from the queue at once. Each row's context is built from the ledger as it is at that moment, and a row sorted meanwhile, or the other half of a transfer this run just linked (both halves are claimed when a twin is applied), is skipped rather than asked or linked twice. Codex's service turns runs away under load (we saw bursts of "403 Forbidden" on its websocket); such rows go back to the front of the queue, the pool drops a slot and pauses 5 s, doubling to 30 s, then adds slots back after three clean runs; a row gets three tries. A row the model skips is retried once at the back of the queue. A usage limit stops the run and says how many rows were not reached. Every row ends in exactly one outcome (organized or ready for review, waiting for review, nothing to suggest, already sorted or linked, failed), the heading shows "Organizing N of M · K applied" with the slots busy (and "Codex is busy, retrying in N s" while paused), and the closing toast lists the counts, which add up to the total; a row Codex organized that still has an unsorted part (for example only "Paid Priya") is called out, and a row whose suggestion is fully applied no longer keeps a green star, so the Unsorted and Suggested chips match the summary. Codex failures are written to the private `logs/codex.log` (the reason only, never the prompt). It works with the Smart organizing switch off. While Codex is connected and suggestions are in use, each unsorted row carries a star in the shape column: a grey outline when there is no suggestion (not asked yet, nothing to suggest, dismissed or failed, with the reason on hover), a pulsing star while Codex is asking, and a filled accent star when a suggestion is waiting. Sorted rows have none. A Suggested filter (with a count) lists the rows with a waiting suggestion; when the run ends, a toast offers to show them. Opening a starred row shows its suggestion; Apply moves to the next suggested row as the flow does (skipping a twin it just linked). The batch uses the Smart organizing model and reasoning level.
- **Apply automatically** (a switch in the Organize heading and under Smart organizing in Settings → Codex, stored as `autoApply`). The button becomes Organize all unsorted: each batch answer is applied as it lands, without review, through the same gestures as Apply (success toasts are held until the run ends; errors still show). The row you open with Smart organizing on is applied too, without moving on. Low-confidence suggestions are never auto-applied; they keep their filled star for review. A new tag suggested by several rows is created once. An Auto-applied filter lists every row Codex organized this session, and each change can be undone as usual.

## Verification

- `node --test tests/desktop/codex.test.cjs`: validators for all four features, the tag merge (portions, rules, recovery copy, versions), settings and consent, organize caching, and CLI discovery through an explicit prefix. No Codex calls.
- `node scripts/smoke-codex.cjs [--model gpt-6-luna] [--install] [--only …]`: the real app against an isolated synthetic workspace (`scripts/codex-demo-data.cjs`) and the Codex CLI signed in on this computer. It connects and configures Codex, runs Smart organizing on six rows (groceries, a savings transfer, a friend settling up, fuel during an event, a new pet tag, an e-transfer to a friend), then approves missing tags, a restructure and aliases, checking the workspace after each, runs Suggest for all unsorted and applies three suggested rows in a row, then, on fresh workspaces, Organize all unsorted with Apply automatically on and a restructure from no structure at all. `--install` also installs Codex into a private prefix with an empty `CODEX_HOME` and opens the sign-in page, then cancels. It records one video per feature under `private/validation/codex-<time>/videos`. It uses the account's Codex limits and sends only invented data.

## Known limits

- Suggestions are only as good as the model and the history; the reviews exist because they can be wrong. Validators guarantee that applied changes are valid, not that they are wise.
- Login completes in the browser on the machine running Urbanomics; the app cannot finish it for you.
- Transaction rules (tags applied to future imports) are not suggested yet; aliases are.
